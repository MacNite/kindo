Einrichtung mit Docker

Kindo kommt als zwei Container-Images und läuft mit Docker Compose neben einer PostgreSQL. Fünf Minuten von null bis zum ersten Bildschirm eurer Familie.

Schnelleinrichtung

  1. Compose-Datei und Beispielkonfiguration holen. 
    mkdir kindo && cd kindo
curl -O https://raw.githubusercontent.com/MacNite/kindo/main/docker-compose.yml
curl -o .env https://raw.githubusercontent.com/MacNite/kindo/main/.env.example
  2. Die zwei Pflichtwerte in .env setzen. 
    POSTGRES_PASSWORD=ein-langes-zufaelliges-passwort
KINDO_SECRET_KEY=$(openssl rand -base64 32)   # Ausgabe einfügen, gut aufbewahren
APP_URL=https://kindo.example.home            # empfohlen: die Adresse, die die Familie öffnet

    Behaltet KINDO_SECRET_KEY: Er signiert Sitzungen und verschlüsselt die Passwörter der Integrationen. Ändert er sich, sind alle abgemeldet und gespeicherte Zugangsdaten unlesbar.

  3. Starten. 
    docker compose up -d

    Der Dienst migrate spielt einmal die Datenbank-Migrationen ein und beendet sich; die App wartet auf ihn.

  4. http://<host>:3000 öffnen und Haushalt und Admin-Login anlegen, oder Mit der Demo-Familie starten ankreuzen, um sich erst umzusehen.
Um aus dem Quellcode zu bauen statt die Images zu laden: Repository klonen und docker compose up -d --build ausführen.

Voraussetzungen

HostLinux mit Docker und Compose v2. linux/amd64; linux/arm64 (z. B. Raspberry Pi 4/5) ab Release-Tags.
RessourcenKeine besondere Hardware: ein kleiner Heimserver oder NAS, auf dem schon Docker läuft. Platz für die Datenbank und den Foto-Cache (standardmäßig 500 MB).
BildschirmeJeder aktuelle Browser. An der Wand: ein Android-Tablet mit Chrome (https) oder ein Kiosk-Browser wie Fully Kiosk Browser. Handys: als PWA installierbar.
NetzwerkEin veröffentlichter Port (3000). https über einen Reverse Proxy wird empfohlen und ist für das Wachhalten des Wand-Bildschirms und die PWA nötig.

Dienste

DienstAufgabe
dbPostgreSQL 17. Daten in ./data/postgres (POSTGRES_DATA_PATH). Nur innerhalb des Compose-Netzes erreichbar.
migrateSpielt ausstehende Migrationen ein und beendet sich. Mit KINDO_DEMO=true lädt er die Demo-Familie in eine leere Datenbank.
appDer Kindo-Server auf Port 3000 (APP_PORT). Startet, sobald migrate fertig ist. Führt die Hintergrundjobs aus: Kalender-, Kontakt- und Fotoabgleich, Ferien-Feeds, Home Assistant.

Konfiguration

Alle Einstellungen stehen in .env; .env.example erklärt jede einzelne. Die wichtigsten:

VariableBedeutung
POSTGRES_PASSWORDPflicht. Das Datenbank-Passwort.
KINDO_SECRET_KEYPflicht. Mindestens 32 Zeichen: openssl rand -base64 32.
APP_URLDie Adresse, die die Familie öffnet; setzt die Anmelde-Rückrufe und Secure-Cookies bei https.
KINDO_TRUSTED_ORIGINSWeitere Adressen, durch Komma getrennt (z. B. eine LAN-IP neben dem Hostnamen).
APP_PORTPort auf dem Host, Standard 3000.
TZZeitzone des Haushalts für das tägliche Zurücksetzen und den Abgleich, Standard Europe/Berlin.
APP_IMAGE, MIGRATE_IMAGEImage-Tags; für reproduzierbare Installationen eine Version festlegen.
OIDC_ISSUER, OIDC_CLIENT_ID, OIDC_CLIENT_SECRETSingle Sign-on. Redirect-URI <APP_URL>/api/auth/callback/oidc.
KINDO_PASSWORD_LOGINfalse lässt nur noch Single Sign-on zu.
GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRETGoogle Kalender über euren eigenen OAuth-Client.
KINDO_TRUST_PROXYtrue nur hinter einem Reverse Proxy, der der einzige Zugang ist.
KINDO_SYNC_MINUTESAbgleich-Intervall der Kalender, Standard 5.
KINDO_PHOTO_CACHE_MBGröße des Foto-Caches, Standard 500.
LOG_LEVELdebug, info, warn oder error; eine JSON-Zeile pro Eintrag.

Die Wandanzeige

Auf dem Tablet /pair öffnen. Es zeigt einen Code und einen QR-Code; ein Admin bestätigt ihn unter Einstellungen → Geräte. Danach zeigt das Tablet die Wand und die Kinderansicht ohne Login; alles über das Abhaken hinaus fragt nach der Einstellungs-PIN.

/wall hält den Bildschirm wach (https oder Kiosk-Browser). Androids eigenen Bildschirmschoner ausschalten und die Bildschirm-Zeitüberschreitung hochsetzen, damit Kindos Bilderrahmen erscheint. Die vollständige Checkliste steht in der README.

Reverse Proxy

Für https Kindo hinter Traefik, Caddy oder nginx stellen. APP_URL auf die öffentliche Adresse und KINDO_TRUST_PROXY=true setzen. Der Live-Abgleich nutzt Server-Sent Events auf /api/stream; dort die Pufferung der Antworten abschalten. Ein minimales Caddyfile:

kindo.example.home {
  reverse_proxy localhost:3000 {
    flush_interval -1
  }
}

Updates und Backups

docker compose pull && docker compose up -d      # Update; Migrationen laufen automatisch
docker compose exec db pg_dump -U kindo kindo > kindo.sql   # Backup

Oder das Verzeichnis ./data/postgres bei gestopptem Stack sichern.
