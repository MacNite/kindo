Setup with Docker

Kindo ships as two container images and runs with Docker Compose next to a PostgreSQL. Five minutes from nothing to your family's first screen.

Quick setup

  1. Get the compose file and the example configuration. 
    mkdir kindo && cd kindo
curl -O https://raw.githubusercontent.com/MacNite/kindo/main/docker-compose.yml
curl -o .env https://raw.githubusercontent.com/MacNite/kindo/main/.env.example
  2. Set the two required values in .env. 
    POSTGRES_PASSWORD=a-long-random-password
KINDO_SECRET_KEY=$(openssl rand -base64 32)   # paste the output, keep it safe
APP_URL=https://kindo.example.home            # recommended: the address the family opens

    Keep KINDO_SECRET_KEY: it signs sessions and encrypts the integrations' passwords. Changing it signs everyone out and makes stored secrets unreadable.

  3. Start it. 
    docker compose up -d

    The migrate service applies the database migrations once and exits; the app waits for it.

  4. Open http://<host>:3000 and set up your household and your admin login, or tick Start with the demo family to look around first.
To build from source instead of pulling the images, clone the repository and run docker compose up -d --build.

Requirements

HostLinux with Docker and Compose v2. linux/amd64; linux/arm64 (e.g. Raspberry Pi 4/5) from release tags.
ResourcesNo special hardware: a small home server or NAS that already runs Docker. Disk for the database plus the photo cache (500 MB by default).
ScreensAny current browser. The wall: an Android tablet with Chrome (https) or a kiosk browser such as Fully Kiosk Browser. Phones: installable as a PWA.
NetworkOne published port (3000). https through a reverse proxy is recommended, and needed for the wall's screen wake lock and the PWA.

Technical data

App imageghcr.io/macnite/kindo: Next.js standalone server on node:26-alpine, non-root user kindo (uid 1001), healthcheck /api/health including a database round-trip
Migration imageghcr.io/macnite/kindo-migrate: one-shot prisma migrate deploy, the only image with the Prisma CLI
Tagslatest, main, sha-<short>, and 1.2.3 / 1.2 for releases. Pin the same version on both images.
Supply chainPublished only after the full CI suite passed for that commit; provenance attestations and an SBOM on every image
StackNext.js 15 (App Router), React 19, TypeScript, Tailwind CSS, Prisma 6, PostgreSQL 17, Server Actions, Server-Sent Events over PostgreSQL LISTEN/NOTIFY for live sync between screens
Sign-inLocal logins (better-auth) and single sign-on with any OpenID Connect provider (authentik, Keycloak …). Wall tablets are paired by code or QR and need no login; a settings PIN guards them.
LanguagesEnglish and German, with separate language and region formats
DataEverything in PostgreSQL (./data/postgres); proxied photos in the kindo-cache volume. Integration secrets are encrypted at rest and never reach the browser.

Services

ServiceWhat it does
dbPostgreSQL 17. Data in ./data/postgres (POSTGRES_DATA_PATH). Only reachable inside the compose network.
migrateApplies pending migrations, then exits. With KINDO_DEMO=true it loads the demo family into an empty database.
appThe Kindo server on port 3000 (APP_PORT). Starts after migrate completed. Runs the background jobs: calendar, contact and photo sync, holiday feeds, Home Assistant.

Configuration

All settings live in .env; .env.example documents every one. The most important:

VariableMeaning
POSTGRES_PASSWORDRequired. The database password.
KINDO_SECRET_KEYRequired. At least 32 characters: openssl rand -base64 32.
APP_URLThe address the family opens; sets the sign-in callbacks and Secure cookies for https.
KINDO_TRUSTED_ORIGINSFurther addresses, comma-separated (e.g. a LAN IP next to the hostname).
APP_PORTHost port, default 3000.
TZThe household's time zone for the daily reset and sync, default Europe/Berlin.
APP_IMAGE, MIGRATE_IMAGEImage tags; pin a version for reproducible deployments.
OIDC_ISSUER, OIDC_CLIENT_ID, OIDC_CLIENT_SECRETSingle sign-on. Redirect URI <APP_URL>/api/auth/callback/oidc.
KINDO_PASSWORD_LOGINfalse makes single sign-on the only way in.
GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRETGoogle Calendar through your own OAuth client.
KINDO_TRUST_PROXYtrue only behind a reverse proxy that is the only way in.
KINDO_SYNC_MINUTESCalendar sync interval, default 5.
KINDO_PHOTO_CACHE_MBPhoto cache size, default 500.
LOG_LEVELdebug, info, warn or error; one JSON line per entry.

The wall display

Open /pair on the tablet. It shows a code and a QR code; an admin confirms it in Settings → Devices. The tablet then shows the wall and the child view without a login; anything beyond ticking things off asks for the settings PIN.

Open /wall to keep the screen on (https or a kiosk browser). Turn Android's own screensaver off and its screen timeout up, so Kindo's photo frame shows. The README has the full checklist.

Reverse proxy

Put Kindo behind Traefik, Caddy or nginx for https. Set APP_URL to the public address and KINDO_TRUST_PROXY=true. The live sync uses Server-Sent Events on /api/stream; disable response buffering there. A minimal Caddyfile:

kindo.example.home {
  reverse_proxy localhost:3000 {
    flush_interval -1
  }
}

Updates and backups

docker compose pull && docker compose up -d      # update; migrations run automatically
docker compose exec db pg_dump -U kindo kindo > kindo.sql   # backup

Or back up the ./data/postgres directory while the stack is stopped.
